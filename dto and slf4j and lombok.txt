SLF4J Introduction with Best Example
What is SLF4J?
SLF4J (Simple Logging Facade for Java) is a logging abstraction framework. It provides a common API for different logging frameworks such as:

Logback

Log4j2

java.util.logging (JUL)

Instead of directly using Log4j or Logback APIs, developers write logging code using SLF4J. Later, they can switch the underlying logging framework without changing application code.

Why Use SLF4J?
✅ Decouples application code from logging implementation

✅ Better performance using parameterized logging

✅ Easy to switch logging frameworks

✅ Industry standard for Spring Boot applications

Logging Levels
Level	Purpose
TRACE	Detailed debugging information
DEBUG	Developer debugging messages
INFO	General application flow
WARN	Warning messages
ERROR	Error situations

Spring Boot already includes SLF4J and Logback through starter dependencies.

Basic SLF4J Example
ProductService.java
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;

public class ProductService {

    private static final Logger logger =
            LoggerFactory.getLogger(ProductService.class);

    public void addProduct() {

        logger.trace("Trace Message");

        logger.debug("Debug Message");

        logger.info("Product creation started");

        logger.warn("Product price is not provided");

        logger.error("Unable to save product");

        logger.info("Product created successfully");
    }
}
Output
INFO  Product creation started
WARN  Product price is not provided
ERROR Unable to save product
INFO  Product created successfully
By default, TRACE and DEBUG logs may not appear depending on configuration.

Best Practice: Parameterized Logging

✅ Use Placeholders

            101,
            "Laptop",

Real-Time Spring Boot Example
Product Controller
@RestController
@RequestMapping("/products")
public class ProductController {

    private static final Logger logger =
            LoggerFactory.getLogger(ProductController.class);

    @GetMapping("/{id}")
    public ResponseEntity<String> getProduct(
            @PathVariable Long id) {

        logger.info("Fetching product with id {}", id);

        try {

            if(id <= 0) {
                logger.warn("Invalid product id {}", id);
                return ResponseEntity.badRequest()
                        .body("Invalid Product Id");
            }

            logger.info("Product fetched successfully");

            return ResponseEntity.ok("Laptop");

        } catch (Exception ex) {

            logger.error("Error while fetching product {}", id, ex);

            return ResponseEntity.internalServerError()
                    .body("Something went wrong");
        }
    }
}

What is Lombok?
Lombok is a Java library that reduces boilerplate code by automatically generating:

Getters

Setters

Constructors

toString()

Without Lombok, Java classes become lengthy because of repetitive code. Lombok helps keep classes clean and readable.

Why Use Lombok?
Without Lombok

    private String productName;

    public Product() {
    }

        this.productName = productName;

DTO (Data Transfer Object) Introduction with Real-Time Spring Boot Application
What is DTO?
DTO (Data Transfer Object) is a design pattern used to transfer data between different layers of an application (Controller, Service, Repository) or between the client and server.

A DTO contains only the data required for a specific operation and helps hide unnecessary entity details from clients.

Simple Definition
DTO is an object used to transfer data between layers without exposing the actual Entity.

Why Do We Need DTO?
Suppose we have a Product Entity:

public class Product {

    private Long productId;
    private String productName;
    private Double price;
    private String supplierName;
    private String internalCode;
    private LocalDateTime createdDate;
}
If we return this Entity directly to the client:

@GetMapping("/{id}")
public Product getProduct(@PathVariable Long id) {
    return productService.getProduct(id);
}
Response:

{
  "productId": 101,
  "productName": "Laptop",
  "price": 50000,
  "supplierName": "ABC Suppliers",
  "internalCode": "P001",
  "createdDate": "2026-06-09T10:00:00"
}
The client receives unnecessary information.

Solution: DTO
Create a DTO containing only required fields.

public class ProductResponseDTO {

    private Long productId;
    private String productName;
    private Double price;
}
Response:

{
  "productId": 101,
  "productName": "Laptop",
  "price": 50000
}
Now sensitive/internal fields are hidden.

Benefits of DTO
Security
Hide sensitive fields.

password
internalCode
salary
Better API Design
Return only necessary data.

Loose Coupling
Changes in Entity won't affect API responses.

Validation Support
DTOs can contain validation annotations.

Service Layer
@Service
public class ProductService {

    public ProductResponseDTO saveProduct(
            ProductRequestDTO requestDTO) {

        Product product = new Product();

        product.setProductId(101L);
        product.setProductName(requestDTO.getProductName());
        product.setPrice(requestDTO.getPrice());

                .productId(product.getProductId())
                .productName(product.getProductName())
                .price(product.getPrice())
                .build();
    }

@RestController

@RequiredArgsConstructor
public class ProductController {

    private final ProductService productService;

    @PostMapping
    public ResponseEntity<ProductResponseDTO>
            createProduct(
            @Valid @RequestBody ProductRequestDTO dto) {

        ProductResponseDTO response =
                productService.saveProduct(dto);

        return ResponseEntity.status(HttpStatus.CREATED)
                .body(response);
    }
}

Spring Boot Validations with Real-Time Example
What is Validation?
Validation is the process of checking whether incoming data is correct before processing it.

For example, when a user creates a product:

Product Name should not be empty.

Price should be greater than 0.

Email should be in valid format.

If invalid data is received, the application should reject the request and return a meaningful error message.

Why Do We Need Validation?
Without validation:

{
  "productName": "",
  "price": -100
}
Invalid data gets stored in the database.

With validation:

{
  "message": "Validation Failed"
}
The request is rejected before reaching business logic.

Global Exception Handling for Validation Errors
Create a Global Exception Handler.

GlobalExceptionHandler.java
import org.springframework.web.bind.MethodArgumentNotValidException;
import org.springframework.web.bind.annotation.*;

import java.util.HashMap;
import java.util.Map;

@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(
            MethodArgumentNotValidException.class)
    public Map<String, String> handleValidation(
            MethodArgumentNotValidException ex) {

        Map<String, String> errors = new HashMap<>();

        ex.getBindingResult()
                .getFieldErrors()
                .forEach(error ->
                        errors.put(
                                error.getField(),
                                error.getDefaultMessage()));

        return errors;
    }
}

Interview Questions
What is @Valid?
@Valid triggers validation on the incoming request object before the controller method executes.

What happens if validation fails?
Spring Boot throws MethodArgumentNotValidException.

Where should validations be placed?
In Request DTO classes, not in Entities.

Why use Global Exception Handling?
To return clean, consistent, and user-friendly validation error responses.
