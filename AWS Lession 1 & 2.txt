Cloud computing means using computing resources over the internet instead of owning and maintaining the physical infrastructure yourself.

These resources include:

Servers

Traditional IT

Lesson 2 — AWS Account + IAM

In Lesson 1, we learned that IAM controls access to AWS resources.

1. What is IAM?

IAM = Identity and Access Management

IAM answers two questions:

Who are you?
What are you allowed to do?

For example:

Developer
    ↓
IAM
    ↓
Can access EC2
Cannot delete S3 buckets
Can read S3 files

So:

Authentication = Who are you?
Authorization = What are you allowed to do?

                       AWS Account

                            |

When you create an AWS account, you get access to the AWS environment.

     +-- RDS
     +-- VPC
     +-- Lambda

The account contains your AWS resources.

4. Root User

When you initially create an AWS account, you have a root user.

The root user has very broad access to the account.

Important rule

Don't use the root user for everyday AWS administration.

Instead:

Root User
    ↓

    ↓
Create IAM administrative access
    ↓
Use IAM for normal work

Enable MFA on the root account.

An IAM user represents an identity that can interact with AWS.

For example:

     |

     +-- Developer2

Each user can have permissions.

Example:

Developer1
    ↓

    ↓

Imagine your company has:

 |

7. What is an IAM Group?

An IAM Group is a collection of IAM users.

For example:

Developers
   |

   ├── Anil
   └── Priya

     ↓

8. Why Groups?

Suppose you have 50 developers.

Without groups:

Developer 1 → EC2 Policy
Developer 2 → EC2 Policy
Developer 3 → EC2 Policy
...
Developer 50 → EC2 Policy

With a group:

Developers Group
       ↓
    EC2 Policy
       ↓
50 Developers

Much easier to manage.

9. What is an IAM Policy?

A policy defines permissions.

It answers:

What actions can this identity perform on which AWS resources?

For example:

Allow
EC2
StartInstances

or:

Allow
S3
Read Objects
10. Policy Structure

AWS policies are written in JSON.

A simplified example:

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": "s3:GetObject",
      "Resource": "*"
    }
  ]
}

Let's understand it.

Version
"Version": "2012-10-17"

Policy language version.

Effect
"Effect": "Allow"

Permission is granted.

It can also be:

"Effect": "Deny"
Action
"Action": "s3:GetObject"

The user can read S3 objects.

Resource
"Resource": "*"

The policy applies to the specified resource scope represented here by *.

11. Simple Policy Example

Suppose we want a developer to start and stop EC2 instances.

Conceptually:

{
  "Effect": "Allow",
  "Action": [
    "ec2:StartInstances",
    "ec2:StopInstances"
  ],
  "Resource": "*"
}

This means:

Allow
  ↓
EC2
  ↓
Start + Stop
12. Managed Policies vs Inline Policies

There are two useful policy concepts to understand initially.

Managed Policy

A reusable policy that can be attached to identities.

Policy
  ↓
Group
  ↓
Users

AWS provides many predefined managed policies.

For example:

AdministratorAccess
AmazonS3ReadOnlyAccess
AmazonEC2ReadOnlyAccess

AWS also allows you to create customer-managed policies.

Inline Policy

A policy embedded directly into a particular identity.

Conceptually:

User
 |
 └── Inline Policy

For beginners, focus first on managed policies and least-privilege permissions.

13. What is an IAM Role?

This is extremely important.

An IAM Role is an identity with permissions that can be assumed by a trusted entity.

Unlike an IAM user, a role is not normally associated with one specific human identity.

Roles are heavily used by AWS services.

14. Why Does EC2 Need a Role?

Suppose your Spring Boot application running on EC2 needs to upload files to S3.

You could imagine giving credentials to the application, but you should not hard-code AWS access keys inside your Java code.

Instead:

Spring Boot
     ↓
EC2
     ↓
IAM Role
     ↓
S3 Permissions
     ↓
S3

This is a much better architecture.

15. EC2 + IAM Role Example

Suppose your application needs:

S3 PutObject
S3 GetObject

Create:

EC2-S3-Role

Attach appropriate S3 permissions:

EC2-S3-Role
      |
      ↓
S3 Policy
      |
      ├── GetObject
      └── PutObject

Attach the role to the EC2 instance.

Then:

Spring Boot
     ↓
EC2
     ↓
IAM Role
     ↓
AWS credentials provided through the role mechanism
     ↓
S3

Your Java application doesn't need hard-coded access keys.

This is the most important part of today's lesson.

 ↓

18. Authentication vs Authorization

Another important interview topic.

Authentication

Determines:

Who are you?

Example:

Username
+
Password
+
MFA
Authorization

Determines:

What can you do?

Example:

User
 ↓
Can read S3
Cannot delete S3

So:

Authentication
      ↓
Who are you?
      ↓
Authorization
      ↓
What can you access?
19. MFA

MFA = Multi-Factor Authentication

Instead of only:

Username
+
Password

you use an additional authentication factor.

Password
   +
Authenticator / security factor

For AWS accounts, MFA is an important security control, particularly for privileged access.

20. Least Privilege

This is one of the most important security principles.

Suppose your application only needs:

S3 → Read

Don't give it:

AdministratorAccess

Instead give only the permissions it requires.

Required:
S3 GetObject

Avoid:
All AWS permissions

This is called:

Principle of Least Privilege

26. Important Security Rules

As you learn AWS, remember these rules:

Rule 1

Don't use the root user for everyday work.

Rule 2

Enable MFA for privileged accounts.

Rule 3

Don't hard-code AWS access keys in Java code.

Bad:

String accessKey = "AKIA...";
String secretKey = "xxxxxxxx";

Never put credentials like this in source code.

Rule 4

Prefer IAM roles for AWS workloads such as EC2.

EC2
 ↓
IAM Role
 ↓
S3
Rule 5

Use least privilege.

Only required permissions

28. Interview Questions
Q1. What is IAM?

IAM is AWS's service for managing identities and controlling access to AWS resources.

Q2. What is an IAM user?

An IAM user represents an identity that can authenticate and access AWS resources according to its permissions.

Q3. What is an IAM group?

A group is a collection of IAM users to which permissions can be assigned collectively.

Q4. What is an IAM policy?

A policy is a JSON document that defines permissions such as which actions are allowed or denied on specified resources.

Q5. What is an IAM role?

An IAM role is an identity with permissions that can be assumed by trusted users, applications, or AWS services.

Q6. Why use an IAM role with EC2?

It allows applications running on EC2 to obtain AWS permissions without embedding long-term access credentials in application code.

Q7. What is least privilege?

Granting only the permissions required to perform a specific task.

Q8. Authentication vs authorization?
Authentication → Who are you?
Authorization   → What can you do?
