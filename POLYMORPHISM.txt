1. First understand the relationship

In object-oriented programming, two important concepts are:

Inheritance → one class gets properties and behaviors from another class.
Polymorphism → one thing can behave in different ways.

A simple real-world example:

Vehicle

Car
Bike
Bus

All are vehicles, but each behaves differently.

                 Vehicle
                    |
          ---------------------
          |         |         |
         Car       Bike      Bus

Here:

Vehicle → Parent/Superclass
Car, Bike, Bus → Child/Subclasses
2. What is Inheritance?

Inheritance is the mechanism by which one class acquires the properties and methods of another class.

Java uses the extends keyword.

Basic syntax
class Parent {
    // properties
    // methods
}

class Child extends Parent {
    // additional properties
    // additional methods
}
3. Very Simple Example
class Animal {

    void eat() {
        System.out.println("Animal is eating");
    }
}

class Dog extends Animal {

    void bark() {
        System.out.println("Dog is barking");
    }
}

Now:

public class Test {

    public static void main(String[] args) {

        Dog d = new Dog();

        d.eat();
        d.bark();
    }
}

Output:

Animal is eating
Dog is barking

Why can Dog call eat()?

Because:

class Dog extends Animal

means:

Dog IS-A Animal

So the Dog object gets access to inherited methods from Animal.

9. Does Java support Multiple Inheritance?

Java does not support multiple inheritance through classes.

This is not allowed:

class A {
}

class B {
}

class C extends A, B {   // ERROR
}

Why?

Because of the Diamond Problem / ambiguity.

       A       B
        \     /
          C

Suppose both A and B contain:

void display()

Then:

C c = new C();

c.display();

Which display() should execute?

Java avoids this ambiguity by not allowing multiple inheritance with classes.

However, Java supports multiple inheritance through interfaces.

interface A {
    void display();
}

interface B {
    void display();
}

class C implements A, B {

    public void display() {
        System.out.println("C display");
    }
}
10. Now let's understand Polymorphism

This is one of the most important Core Java concepts.

The word polymorphism comes from:

Poly = Many
Morph = Forms

So:

One thing can take many forms.

In Java, polymorphism mainly has two types:

                 Polymorphism
                      |
             ------------------
             |                |
       Compile-time       Runtime
       Polymorphism       Polymorphism
             |                |
       Method Overloading  Method Overriding
11. Compile-Time Polymorphism

Compile-time polymorphism is achieved through method overloading.

Example:

class Calculator {

    int add(int a, int b) {
        return a + b;
    }

    int add(int a, int b, int c) {
        return a + b + c;
    }

    double add(double a, double b) {
        return a + b;
    }
}

Now:

Calculator c = new Calculator();

System.out.println(c.add(10, 20));

System.out.println(c.add(10, 20, 30));

System.out.println(c.add(10.5, 20.5));

Output:

30
60
31.0

Same method name:

add()

Different parameter lists.

That's method overloading.

12. What can change in Method Overloading?

You can change:

Number of parameters
void display(int a) {
}

void display(int a, int b) {
}
Data type
void display(int a) {
}

void display(double a) {
}
Order of parameters
void display(int a, double b) {
}

void display(double a, int b) {
}

But this is not overloading:

int display(int a) {
    return a;
}

double display(int a) {
    return a;
}

Only return type is different.

❌ Not allowed.

13. Runtime Polymorphism

This is more important for interviews.

Runtime polymorphism is achieved using:

Method overriding + inheritance

Example:

class Animal {

    void sound() {
        System.out.println("Animal makes sound");
    }
}

Child:

class Dog extends Animal {

    @Override
    void sound() {
        System.out.println("Dog barks");
    }
}

Another child:

class Cat extends Animal {

    @Override
    void sound() {
        System.out.println("Cat meows");
    }
}

Now:

Dog d = new Dog();
d.sound();

Cat c = new Cat();
c.sound();

Output:

Dog barks
Cat meows
14. The Most Important Concept: Parent Reference → Child Object

Look carefully at this:

Animal a = new Dog();

This is the foundation of runtime polymorphism.

The reference type is:

Animal

The actual object is:

Dog

Diagram:

Animal a
   |
   | reference
   ↓
+-----------+
|   Dog     |
|           |
| sound()   |
+-----------+

Now:

a.sound();

Which sound() executes?

Dog's sound() executes.

Output:

Dog barks

Why?

Because Java determines the overridden instance method based on the actual object at runtime.

15. Multiple Objects Using Same Parent Reference

This is where polymorphism becomes powerful.

class Animal {

    void sound() {
        System.out.println("Animal sound");
    }
}

class Dog extends Animal {

    @Override
    void sound() {
        System.out.println("Dog barks");
    }
}

class Cat extends Animal {

    @Override
    void sound() {
        System.out.println("Cat meows");
    }
}

Now:

public class Test {

    public static void main(String[] args) {

        Animal a;

        a = new Dog();
        a.sound();

        a = new Cat();
        a.sound();
    }
}

Output:

Dog barks
Cat meows

The same reference:

Animal a

can refer to different objects:

Animal a → Dog
Animal a → Cat

This is runtime polymorphism.

19. Very Important Interview Question

Consider:

Animal a = new Dog();

What are the two different things?

Reference type
Animal
Object type
Dog

Remember:

Reference type determines what members are accessible at compile time.

Actual object type determines which overridden instance method executes at runtime.

This distinction is extremely important.

20. Example
class Animal {

    void eat() {
        System.out.println("Animal eating");
    }
}

class Dog extends Animal {

    @Override
    void eat() {
        System.out.println("Dog eating");
    }

    void bark() {
        System.out.println("Dog barking");
    }
}

Now:

Animal a = new Dog();

a.eat();

Output:

Dog eating

But:

a.bark();

❌ Compilation error.

Why?

Because reference type is:

Animal

Animal doesn't know about bark().

21. How to access the child-specific method?

We can use casting:

Animal a = new Dog();

Dog d = (Dog) a;

d.bark();

This is called downcasting.

But you should be careful.

This is dangerous:

Animal a = new Cat();

Dog d = (Dog) a;

It will produce:

ClassCastException

because the actual object is Cat, not Dog.

22. Upcasting

This is very common and safe:

Dog d = new Dog();

Animal a = d;

or simply:

Animal a = new Dog();

This is called upcasting.

Diagram:

        Animal
           ↑
           |
          Dog

Child → Parent reference.

23. @Override Annotation

When overriding a method, we normally use:

@Override
void sound() {
    System.out.println("Dog barks");
}

Why?

It tells the compiler:

"I intend to override a parent method."

If you accidentally make a mistake:

@Override
void sounds() {
}

The compiler will identify the problem.

So @Override improves safety and readability.

24. Method Overloading vs Overriding

This is a must-know interview comparison.

Feature	Overloading	Overriding
Polymorphism	Compile-time	Runtime
Class relationship	Usually same class	Parent-child
Method name	Same	Same
Parameters	Must be different	Normally same
Return type	Cannot differ only by return type	Same/covariant
Inheritance required?	No	Yes
Binding	Static/Early binding	Dynamic/Late binding

Simple memory trick:

OVERLOADING  → Same class → Different parameters
OVERRIDING   → Parent/Child → Same method signature
25. Constructor and Inheritance

Constructors are not inherited.

Example:

class Parent {

    Parent() {
        System.out.println("Parent constructor");
    }
}

class Child extends Parent {

    Child() {
        System.out.println("Child constructor");
    }
}

Now:

Child c = new Child();

Output:

Parent constructor
Child constructor

The parent constructor executes first.

Why?

Because the child object contains the inherited parent state, which must be initialized first.

26. super Keyword

super refers to the parent class.

Example:

class Animal {

    String name = "Animal";

    void display() {
        System.out.println("Animal display");
    }
}

Child:

class Dog extends Animal {

    String name = "Dog";

    void show() {

        System.out.println(name);

        System.out.println(super.name);

        super.display();
    }
}

Usage:

Dog d = new Dog();

d.show();

Output:

Dog
Animal
Animal display

So:

super.name

means parent class variable.

And:

super.display()

means parent class method.

27. Complete Example

Let's combine everything.

class Employee {

    void work() {
        System.out.println("Employee is working");
    }
}

class Developer extends Employee {

    @Override

        System.out.println("Developer writes code");
    }

class Tester extends Employee {

    @Override

        System.out.println("Tester tests application");
    }
}

class Manager extends Employee {

    @Override

    }

Main:

public class Test {

        employee.work();

        employee = new Tester();
        employee.work();

        employee = new Manager();
        employee.work();
    }
}

Output:

Developer writes code
Tester tests application
Manager manages team

Here:

Employee employee
       |
       +----> Developer
       |
       +----> Tester
       |
       +----> Manager

This is runtime polymorphism.

28. Why is Polymorphism Useful in Real Applications?

Suppose you write:

void processPayment(Payment payment) {
    payment.pay();
}

Now you can pass:

processPayment(new UpiPayment());

processPayment(new CardPayment());

processPayment(new CashPayment());

You don't need:

if (paymentType.equals("UPI")) {
   ...
}
else if (paymentType.equals("CARD")) {
   ...
}
else if (paymentType.equals("CASH")) {
   ...
}

Instead, each class handles its own behavior.

This leads to:

Loose coupling
Extensibility
Cleaner code
Better maintainability
Easier testing
Support for SOLID principles
29. Very Important Mental Model

When you see:

Parent p = new Child();

Think:

             Parent
                ↑
                |
        reference type
                |
                p
                |
                ↓
             Child
          actual object

Then:

p.method();

Ask two questions:

Question 1

Does Parent have the method?

If no → compile-time error.

Question 2

Is the method overridden in Child?

If yes → Child's implementation executes at runtime.
