Explanation of id and name
Attribute	Purpose	Example
id	Uniquely identifies an HTML element. Used by labels, CSS, and JavaScript.	id="email"
name	The key used when form data is submitted to the server.	name="email"
Example:

<label for="email">Email</label>

<input
    type="email"
    id="email"
    name="email">
Here:

for="email" connects the label to the input with id="email".

name="email" is the parameter sent to the server, for example:

fullName=Srinivasa Rao
email=srinivas@gmail.com
password=12345
mobile=9876543210
course=Java
This structure is commonly used with Java Servlets, Spring Boot, JSP, and other backend frameworks.


Explain HTML 5 storage classes with examples

HTML5 provides Web Storage, which allows websites to store data in the browser. Before HTML5, developers mainly used cookies, which had limited storage and were sent with every HTTP request. HTML5 introduced Storage APIs that are faster, larger, and easier to use with JavaScript.

HTML5 Storage Overview
HTML5 Storage
│
├── Local Storage
├── Session Storage
└── Cookies (older method, still supported)
Why Do We Need Storage?
Suppose a user logs into a website.

Without storage:

Open Website
      ↓
Login
      ↓
Refresh Page
      ↓
Login Again
With HTML5 storage:

Open Website
      ↓
Login
      ↓
Store User Information
      ↓
Refresh Page
      ↓
User Information Still Available
1. Local Storage
Definition
Stores data without an expiration time.

Data remains even after closing the browser.

Data is available until it is explicitly removed.

Lifetime
Save Data
     ↓
Close Browser
     ↓
Open Browser Again
     ↓
Data Still Exists
Syntax
localStorage.setItem("key", "value");
Retrieve data:

let value = localStorage.getItem("key");
Delete one item:

localStorage.removeItem("key");
Delete everything:

localStorage.clear();
Example 1: Store Username
<!DOCTYPE html>
<html>
<body>

<h2>Local Storage Example</h2>

<input type="text" id="username">

<button onclick="saveData()">Save</button>

<script>

function saveData(){

let user=document.getElementById("username").value;

localStorage.setItem("username",user);

alert("Saved Successfully");

}

</script>

</body>
</html>
Retrieve Data
<script>

let user=localStorage.getItem("username");

document.write(user);

</script>
Output

Srinivasa Rao
Local Storage Methods
Method	Description
setItem()	Save data
getItem()	Read data
removeItem()	Remove one item
clear()	Remove all data
key()	Get key name
length	Number of stored items
Example
localStorage.setItem("course","Java");

localStorage.getItem("course");

localStorage.removeItem("course");

localStorage.clear();
2. Session Storage
Definition
Stores data only for the current browser tab/session.

When the tab or browser is closed, the data is removed automatically.

Lifetime
Open Browser
      ↓
Store Data
      ↓
Close Tab
      ↓
Data Deleted
Syntax
sessionStorage.setItem("key","value");
Retrieve:

sessionStorage.getItem("key");
Delete:

sessionStorage.removeItem("key");
Clear:

sessionStorage.clear();
Example
<!DOCTYPE html>
<html>
<body>

<button onclick="store()">Store Data</button>

<script>

function store(){

sessionStorage.setItem("city","Hyderabad");

alert("Stored");

}

</script>

</body>
</html>
Retrieve

document.write(sessionStorage.getItem("city"));
Output

Hyderabad
Session Storage Methods
Method	Description
setItem()	Save data
getItem()	Read data
removeItem()	Delete one item
clear()	Delete all items
Local Storage vs Session Storage
Feature	Local Storage	Session Storage
Lifetime	Permanent until removed	Until tab/window is closed
Capacity	About 5–10 MB (browser-dependent)	About 5 MB (browser-dependent)
Shared Across Tabs	Yes (same origin)	No (each tab has its own session)
Survives Browser Restart	Yes	No
Use Case	Remember user preferences, theme, shopping cart	Multi-step forms, temporary session data
3. Cookies
Cookies existed before HTML5 storage.

Example
document.cookie="username=Srinivasa Rao";
Read

document.cookie;
Cookies vs Local Storage
Cookies	Local Storage
Small storage (around 4 KB)	Much larger (around 5–10 MB)
Sent with every HTTP request	Not sent automatically to the server
Can have expiration dates	Remains until removed
Often used for sessions and authentication	Used for client-side application data
Real-Time Examples
Example 1: Dark Mode
User clicks Dark Mode
        ↓
Store Theme in Local Storage
        ↓
Refresh Page
        ↓
Dark Mode Remains Enabled

Summary
Local Storage: Persistent browser storage for long-term client-side data (user preferences, theme, non-sensitive settings).

Session Storage: Temporary storage that lasts only for the current browser tab or window.

Cookies: Small pieces of data often used for server-related sessions and authentication; secure HttpOnly cookies are generally recommended for sensitive session information.
