Spring Boot Relational Mappings – Step-by-Step with Real-Time Examples
In real-world applications, tables are connected to each other. Spring Boot uses JPA/Hibernate annotations to represent these relationships between entities.

There are 4 types of relational mappings:

One-to-One (@OneToOne)

One-to-Many (@OneToMany)

Many-to-One (@ManyToOne)

Many-to-Many (@ManyToMany)

Understanding mappedBy
Without mappedBy:

@OneToMany
private List<Employee> employees;
Hibernate creates an extra join table.

With mappedBy:

@OneToMany(mappedBy = "department")
private List<Employee> employees;
Hibernate uses the existing foreign key.

Cascade Types
cascade = CascadeType.ALL
Means:

SAVE Parent
     ↓
SAVE Child

DELETE Parent
     ↓
DELETE Child
Types
CascadeType.PERSIST
CascadeType.MERGE
CascadeType.REMOVE
CascadeType.REFRESH
CascadeType.DETACH
CascadeType.ALL
Fetch Types
EAGER
@OneToOne(fetch = FetchType.EAGER)
Loads child data immediately.

Person person = repo.findById(1L);
Passport also loads automatically.

LAZY
@OneToMany(fetch = FetchType.LAZY)
Loads child data only when required.

department.getEmployees();
Then Hibernate fetches employees.

Interview Questions
Q1: Difference between OneToMany and ManyToOne?
Answer:

One Department → Many Employees = @OneToMany

Many Employees → One Department = @ManyToOne

Q2: What is mappedBy?
Answer:

Used to avoid creating an extra join table and define the owning side of the relationship.

Q3: What is CascadeType.ALL?
Answer:

All operations (save, update, delete) on parent are propagated to child entities.

Q4: What is the default fetch type?
Mapping	Default Fetch
OneToOne	EAGER
ManyToOne	EAGER
OneToMany	LAZY
ManyToMany	LAZY

2. Employee Entity
Employee is the central entity.

Employee.java
@Entity
@Table(name = "employees")
public class Employee {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long employeeId;

    private String employeeName;

    private String email;

    private Double salary;

    // Many Employees -> One Department
    @ManyToOne
    @JoinColumn(name = "department_id")
    private Department department;

    // One Employee -> One Address
    @OneToOne(cascade = CascadeType.ALL)
    @JoinColumn(name = "address_id")
    private Address address;

    // Many Employees -> Many Projects
    @ManyToMany(cascade = CascadeType.ALL)
    @JoinTable(
            name = "employee_project",
            joinColumns =
            @JoinColumn(name = "employee_id"),
            inverseJoinColumns =
            @JoinColumn(name = "project_id")
    )
    private List<Project> projects = new ArrayList<>();

    // Many Employees -> Many Skills
    @ManyToMany(cascade = CascadeType.ALL)
    @JoinTable(
            name = "employee_skill",
            joinColumns =
            @JoinColumn(name = "employee_id"),
            inverseJoinColumns =
            @JoinColumn(name = "skill_id")
    )
    private List<Skill> skills = new ArrayList<>();
}

REST APIs with relational entities

REST APIs with Relational Entities in Spring Boot
When working with relational mappings (@OneToOne, @OneToMany, @ManyToOne, @ManyToMany), exposing entities directly through REST APIs can cause several issues:

Infinite recursion (StackOverflowError)

Unnecessary data exposure

Large JSON responses

Tight coupling between database and API

Therefore, in real-world projects, we use DTOs (Data Transfer Objects) instead of directly exposing entities.

Service Layer Mapping
@Service
@RequiredArgsConstructor
public class EmployeeService {

    private final EmployeeRepository employeeRepository;
    private final DepartmentRepository departmentRepository;

    public EmployeeResponseDTO getEmployee(Long id) {

        Employee employee =
                employeeRepository.findById(id)
                        .orElseThrow();

        return new EmployeeResponseDTO(

                employee.getEmployeeId(),
                employee.getEmployeeName(),
                employee.getEmail(),
                employee.getSalary(),

                employee.getDepartment()
                        .getDepartmentName(),

                employee.getAddress()
                        .getCity(),

                employee.getProjects()
                        .stream()
                        .map(Project::getProjectName)
                        .toList(),

                employee.getSkills()
                        .stream()
                        .map(Skill::getSkillName)
                        .toList()
        );
    }
}

Service
public EmployeeResponseDTO createEmployee(
        EmployeeRequestDTO dto) {

    Department department =
            departmentRepository.findById(
                    dto.departmentId())
                    .orElseThrow();

    Employee employee = new Employee();

    employee.setEmployeeName(dto.employeeName());
    employee.setEmail(dto.email());
    employee.setSalary(dto.salary());

    employee.setDepartment(department);

    Employee saved =
            employeeRepository.save(employee);

    return mapToDTO(saved);
}

Best Practices for Relational REST APIs
1. Never expose Entity classes directly
❌ Bad

public Employee getEmployee()
✅ Good

public EmployeeResponseDTO getEmployee()
2. Use DTOs
EmployeeRequestDTO
EmployeeResponseDTO
DepartmentResponseDTO
3. Use Validation

@NotNull
@Positive
@Email
4. Use Global Exception Handling
@RestControllerAdvice
public class GlobalExceptionHandler {
}
