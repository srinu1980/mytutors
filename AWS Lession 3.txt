Lesson 3 — Amazon EC2: Your First AWS Virtual Server

Since you already know Java/Spring Boot, think of EC2 as your cloud-based Linux server where you can install Java, Maven, Docker, Nginx and run your Spring Boot applications.

1. What is EC2?

EC2 = Elastic Compute Cloud

EC2 provides virtual servers in AWS.

Instead of buying:

Physical Server
     ↓
CPU + RAM + Disk
     ↓
Operating System
     ↓
Java
     ↓
Spring Boot

you create a virtual server in AWS:

AWS
 ↓
EC2 Instance
 ↓
Linux
 ↓
Java
 ↓
Spring Boot

An EC2 virtual server is called an EC2 instance.

2. EC2 Architecture

The basic architecture is:

                    AWS Region
                        |
                       VPC
                        |
                 ┌──────┴──────┐
                 |              |
             Subnet          Subnet
                 |
              EC2 Instance
                 |
        ┌────────┼────────┐
        ↓        ↓        ↓
      CPU       RAM     Storage
                 |
                 ↓
              Linux
                 |
                 ↓
           Spring Boot

Later, we'll add Load Balancer, RDS and S3.

3. What Do We Need to Create an EC2 Instance?

When launching EC2, you'll encounter these major concepts:

EC2 Instance
 |
 ├── Region
 ├── AMI
 ├── Instance Type
 ├── Key Pair
 ├── Network / Subnet
 ├── Security Group
 ├── Storage
 └── IAM Role

Let's understand each one.

4. AMI

AMI = Amazon Machine Image

An AMI is a template used to create an EC2 instance.

It can contain:

Operating system
Software configuration
Application configuration

For example:

AMI
 |
 └── Ubuntu Linux

When you launch an EC2 instance:

Ubuntu AMI
     ↓
EC2 Instance
Common choices

You may see options such as:

Amazon Linux
Ubuntu
Windows Server
Red Hat
SUSE

For our Java/Spring Boot learning, Ubuntu or Amazon Linux is a good choice.

5. Instance Type

Instance type determines the computing capacity of the EC2 instance.

It determines resources such as:

CPU
Memory
Network performance

Conceptually:

Small Instance
   ↓
Less CPU + RAM

Large Instance
   ↓
More CPU + RAM

AWS instance families are designed for different workloads.

Examples include:

General purpose
Compute optimized
Memory optimized
Storage optimized
Accelerated computing

For learning, choose a small eligible instance type rather than a large production instance.

AWS frequently changes which instance types and free/trial offers are available, so check the current pricing/eligibility before launching.

6. Key Pair

To securely connect to a Linux EC2 instance, you commonly use an SSH key pair.

Key Pair
 |
 ├── Public Key
 └── Private Key

The public key is associated with the instance.

You keep the private key securely.

Example:

my-aws-key.pem
Very important

Never:

Upload .pem to GitHub
Email it publicly
Share it with others
Commit it into your project

Treat the private key like a password.

7. Security Group

A Security Group acts as a virtual firewall for your EC2 instance.

Suppose your Spring Boot application runs on:

Port 8080

You need a suitable inbound rule if you want to access it externally.

Example:

Internet
    |
    ↓
Security Group
    |
    ↓
EC2
    |
    ↓
8080
    |
Spring Boot

Typical ports:

Port	Purpose
22	SSH
80	HTTP
443	HTTPS
8080	Common Spring Boot application port

Security note: For production, don't blindly expose 8080 to the entire internet. Later we'll put a load balancer/reverse proxy in front and restrict access appropriately.

8. Storage

An EC2 instance normally uses EBS (Elastic Block Store) for persistent block storage.

Think:

EC2
 |
 └── EBS Volume
       |
       └── Disk

You can install:

Java
Maven
Git
Docker
Application

on the instance's disk.

9. IAM Role

An EC2 instance can have an IAM role attached.

For example:

EC2
 |

 |
 └── S3 permissions

Then your application can access S3 using the role rather than embedding long-term AWS credentials in your source code.

We'll use this later.

31. Very Important: Don't Leave Resources Running

AWS resources can incur charges.

After practicing, check your resources.

For an EC2 training instance:

EC2
 ↓
Instance
 ↓
Stop instance

Stopping an instance generally stops the instance compute charges, but attached resources such as EBS volumes can still incur charges. Public IPv4 addressing can also have charges under current AWS pricing.

So don't assume:

"I stopped EC2, therefore everything is free."

We'll learn AWS cost management later.

37. EC2 Interview Questions
Q1. What is EC2?

EC2 is an AWS service that provides resizable virtual compute capacity in the cloud.

Q2. What is an EC2 instance?

An EC2 instance is a virtual server running in AWS.

Q3. What is an AMI?

An AMI is a template used to launch EC2 instances, including an operating-system image and associated configuration.

Q4. What is a Security Group?

A Security Group is a virtual firewall controlling inbound and outbound traffic for resources such as EC2 instances.

Q5. What is a Key Pair?

A key pair consists of a public key and private key and can be used to securely authenticate to an EC2 instance.

Q6. What is the difference between Stop and Terminate?

Stop shuts down the instance so it can generally be started again. Terminate removes the EC2 instance.

Q7. Why use IAM Role with EC2?

An IAM role allows applications running on EC2 to obtain temporary AWS permissions without embedding long-term AWS credentials in application code.

Q8. What is EBS?

EBS is AWS block storage that provides persistent storage volumes for EC2.

1. EC2 Networking — Big Picture

When you launch an EC2 instance, it doesn't simply exist "on the internet."

It is placed inside an AWS networking environment.

                         AWS
                          |
                         VPC
                          |
                    ┌─────┴─────┐
                    |           |
                Public        Private
                Subnet        Subnet
                    |
                   EC2
                    |
              Public IPv4
                    |
                 Internet

For today's simple deployment, we'll use an EC2 instance in a public subnet with appropriate routing and security-group rules.

2. What is a VPC?

VPC = Virtual Private Cloud

Think of a VPC as your private network inside AWS.

AWS
 |
 └── VPC
      |
      ├── Subnet
      ├── Route Table
      ├── Internet Gateway
      └── Security Groups

Later, we'll study VPC properly.

For now, remember:

VPC = Your logical network in AWS

3. What is a Subnet?

A subnet is a smaller network inside a VPC.

VPC
 |
 ├── Public Subnet
 |
 └── Private Subnet

A public subnet is associated with routing that can provide internet connectivity through an Internet Gateway.

For today's EC2 application:

Internet
   ↓
Internet Gateway
   ↓
Public Subnet
   ↓
EC2
4. What is an Internet Gateway?

An Internet Gateway (IGW) provides a path between a VPC and the internet.

Conceptually:

Internet
   ↕
Internet Gateway
   ↕
VPC
   ↓
Subnet
   ↓
EC2

A route table needs an appropriate route for internet-bound traffic.

We'll cover this in detail in the VPC lesson.

5. Public IP Address

Your EC2 instance can have a public IPv4 address.

13.xxx.xxx.xxx

Your Browser

      |
      ↓

But a public IP alone does not mean that every connection will work.

The network route and security group must allow the traffic.

26. Very Important: Spring Boot Binding

Spring Boot applications normally need to listen on an interface reachable from outside the machine.

For a basic EC2 deployment, you can configure:

server.address=0.0.0.0
server.port=8080

For example:

server.port=8080
server.address=0.0.0.0

This tells the application to listen on the server's network interfaces rather than only localhost.

27. Why localhost Can Cause Problems

Works

You need the application to listen appropriately and the AWS/network firewall rules to allow the traffic.

37. Interview Questions
Q1. What is SSH?

SSH is a secure protocol used to remotely access and administer servers.

Q2. Why is port 22 used?

Port 22 is the standard port for SSH.

Q3. What is a Security Group?

A Security Group is a stateful virtual firewall that controls network traffic to and from AWS resources such as EC2.

Q4. Why can't I access Spring Boot from the internet?

Check:

Spring Boot is running.
Application is listening on the appropriate interface.
Security Group allows port 8080.
EC2 has suitable network connectivity/public addressing.
VPC route table and Internet Gateway are configured correctly.
Q5. What is the difference between public and private IP?

A private IP is used within the private AWS network, while a public IP can provide internet-facing connectivity when the network configuration permits it.

Q6. Why shouldn't we expose port 8080 in production?

A production architecture normally places the application behind a controlled entry point such as a load balancer or reverse proxy, uses HTTPS, and restricts direct application-port access.
