What is Service Registry in Microservices?
A Service Registry is a central server where all microservices register themselves when they start.

Instead of hardcoding service URLs like:

http://localhost:8081
http://localhost:8082
http://localhost:8083
microservices register with the Service Registry, and other services discover them dynamically.

Why Do We Need Service Registry?
Imagine you have:

Employee Service
Department Service
Project Service
Suppose Employee Service needs to call Department Service.

Without Service Registry:

http://localhost:8082/departments
Problem:

Port may change

Service may move to another server

Multiple instances may exist

Example:

Department Service Instance 1 -> 8082
Department Service Instance 2 -> 8085
Department Service Instance 3 -> 8087
How will Employee Service know which instance to call?

This is where Service Registry helps.

What is API Gateway?
An API Gateway is the single entry point for all client requests in a microservices architecture.

Instead of clients directly calling multiple microservices, all requests first go to the API Gateway, which then routes them to the appropriate service.

Without API Gateway
Suppose we have:

Employee Service → 8081

Department Service → 8082

Project Service → 8083

What is Feign Client in Spring Boot?
Feign Client is a declarative HTTP client used for communication between microservices.

Instead of writing complex code using RestTemplate or WebClient, Feign allows you to call another microservice by simply defining an interface.

Why Do We Need Feign Client?
Suppose:

Employee Service
Department Service
Employee Service needs Department details.

Without Feign Client, you use:

RestTemplate restTemplate = new RestTemplate();

Department department =
        restTemplate.getForObject(
                "http://localhost:8082/departments/1",
                Department.class);
Problems:

More boilerplate code

Manual URL handling

Harder maintenance

With Feign Client
Just create an interface:

@FeignClient(name = "DEPARTMENT-SERVICE")
public interface DepartmentFeignClient {

    @GetMapping("/departments/{id}")
    Department getDepartmentById(@PathVariable Long id);
}
Now call it like a normal Java method:

Department department =
        departmentFeignClient.getDepartmentById(1L);
Feign automatically:

Creates HTTP request

Calls Department Service

Converts JSON to Java Object

Returns response

What is Load Balancing in Spring Boot Microservices?
Load Balancing is the process of distributing incoming requests across multiple instances of the same microservice to improve performance, scalability, and availability.

Why Do We Need Load Balancing?
Suppose you have only one Employee Service instance:

Client
   |
   V
Employee Service (8081)
If 10,000 users send requests simultaneously:

Client Requests
      |
      V
Employee Service (8081)
Problems:

Server becomes overloaded

Slow response time

Application may crash

Solution: Multiple Instances
Run multiple instances of Employee Service:

Employee Service Instance 1 -> 8081
Employee Service Instance 2 -> 8082
Employee Service Instance 3 -> 8083
Now distribute requests among them.

                Client
                   |
                   V
           Load Balancer
           /     |      \
          /      |       \
         V       V        V

      8081     8082     8083
This is called Load Balancing.

Example
Requests arrive:

Request 1
Request 2
Request 3
Request 4
Request 5
Request 6
Load Balancer distributes them:

Request 1 -> Instance 1
Request 2 -> Instance 2
Request 3 -> Instance 3
Request 4 -> Instance 1
Request 5 -> Instance 2
Request 6 -> Instance 3
No single server is overloaded.

Benefits of Load Balancing
1. High Availability
If one instance fails:

8081 -> DOWN
8082 -> UP
8083 -> UP
Requests continue using available instances.

2. Better Performance
Traffic is shared among multiple servers.

3. Scalability
Add more instances when traffic increases.

8081
8082
8083
8084
8085
4. Fault Tolerance
Application remains available even if one instance crashes.

Simple Interview Answer
Load Balancing is a technique used in microservices to distribute requests across multiple instances of the same service. In Spring Boot, it is commonly implemented using Spring Cloud LoadBalancer together with a Service Registry like Netflix Eureka.
