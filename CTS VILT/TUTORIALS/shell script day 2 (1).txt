Factorial of a Number (Recursive Function)


factorial() {
    if [ $1 -le 1 ]; then
        echo 1
    else
        local prev=$(factorial $(( $1 - 1 )))
        echo $(( $1 * prev ))

    fi
}

result=$(factorial 5)
echo "Factorial is: $result"

Text processing in Unix/Linux shell scripting involves using powerful tools to search, extract, format, and transform text data. 

These tools are essential for log analysis, report generation, automation, and scripting tasks.

Common Text Processing Tools in Unix

Tool		Purpose
=========================================
cat		Display contents of a file
grep		Search text using patterns (regex)
cut		Extract specific columns/fields
awk		Pattern scanning and processing
sed		Stream editor for substitution/editing
sort		Sort lines of text files
uniq		Remove duplicate lines
tr		Translate or delete characters
wc		Count words, lines, characters
head/tail	Show beginning or end of files


 Examples of Text Processing

 1. grep – Pattern Matching

grep "error" logfile.txt
grep -i "fail" report.txt     # Case-insensitive


 2. cut – Extract Columns
cut -d ':' -f1 /etc/passwd     # Extract usernames
cut -d ',' -f2 student.csv     # Get second column from CSV

 3. awk – Process Fields and Records

awk '{print $1}' file.txt                # Print first column

 4. sed – Search and Replace

sed 's/foo/bar/' file.txt           # Replace first 'foo' with 'bar'
sed 's/foo/bar/g' file.txt          # Replace all 'foo'
sed -n '2,4p' file.txt              # Print lines 2 to 4

 5. tr – Translate Characters

echo "HELLO" | tr 'A-Z' 'a-z'       # Convert to lowercase
cat file.txt | tr -d '0-9'          # Remove digits


 6. sort and uniq

sort names.txt                      # Alphabetical sort

sort numbers.txt | uniq             # Sort and remove duplicates

uniq -c names.txt                   # Count occurrences of each line


7. wc – Word/Line/Character Count

wc file.txt                         # Lines, words, characters
wc -l file.txt                      # Line count only


 8. head / tail

head -n 5 file.txt                  # First 5 lines

tail -n 10 file.txt                 # Last 10 lines


echo "Total errors today:"
grep "ERROR" /var/log/syslog | wc -l

echo "Top 5 IPs making requests:"
cat access.log | awk '{print $1}' | sort | uniq -c | sort -nr | head -5

Error Handling and Debugging in Unix /Linux
=======================================


Handling Errors with Exit Codes
---------------------------------
In Bash scripting, commands and scripts can indicate success or failure by returning an exit code. 

An exit code of 0 typically signifies success, while any non-zero exit code indicates an error.



Checking Exit Codes
-----------------------
After executing a command, you can access its exit code using the special variable $?

ls /path/to/nonexistent/directory

exit_code=$?

if [ $exit_code -ne 0 ]; then
    echo "An error occurred."
fi




Exit Codes in Functions
---------------------------

When writing functions, you can also use the return statement to specify an exit code. 

check_file_exists()
 {
    if [ -e "$1" ]; then          #It returns True if any type of file exists.
        return 0  # Success
    
   else
   
     return 1  # Error

    fi
}




check_file_exists "filename.txt"

exit_code=$?

if [ $exit_code -ne 0 ]; then
    echo "The file does not exist."
fi



the check_file_exists function checks if a file exists. 
It returns 0 if the file exists (success) and 1 if the file does not exist (error). 

We capture the exit code using $? and display an error message if needed.




Debugging Techniques
======================

Debugging is an essential skill in scripting. 
It helps identify and resolve issues in your code. 
Bash provides several techniques to aid in debugging:


Printing Debug Information
==============================
Adding print statements to your script can help you understand the flow of execution and the values of variables at specific points.


Enabling Debug Mode
--------------------
Bash offers a debug mode (-x) that prints each command and its arguments as they are executed. 

You can enable it by adding set -x at the beginning of your script or
 by running your script with the -x option.



The debug mode provides detailed information about the execution flow, making it easier to identify errors or unexpected behaviors.
