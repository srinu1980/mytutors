3. DepartmentMapper.java

Package: com.example.department.mapper

package com.example.department.mapper;

import com.example.department.dto.DepartmentRequest;
import com.example.department.dto.DepartmentResponse;
import com.example.department.entity.Department;

public class DepartmentMapper {

    private DepartmentMapper() {
        // Prevent object creation
    }

    /**
     * Convert Request DTO -> Entity
     */
    public static Department toEntity(DepartmentRequest request) {

        if (request == null) {
            return null;
        }

        Department department = new Department();

        department.setDepartmentName(request.getDepartmentName());
        department.setDepartmentCode(request.getDepartmentCode());
        department.setDepartmentHead(request.getDepartmentHead());

        return department;
    }

    /**
     * Convert Entity -> Response DTO
     */
    public static DepartmentResponse toResponse(Department department) {

        if (department == null) {
            return null;
        }

        return DepartmentResponse.builder()
                .departmentId(department.getDepartmentId())
                .departmentName(department.getDepartmentName())
                .departmentCode(department.getDepartmentCode())
                .departmentHead(department.getDepartmentHead())
                .build();
    }

}

Why Use DTOs?
Entity	DTO
Represents the database table	Represents API request/response
Contains JPA annotations	No database annotations
May include internal fields	Exposes only required fields
Used by Repository	Used by Controller and Service

Benefits:

Better security (don't expose entity internals)
Easier API evolution
Clear separation between persistence and API layers
Widely used in enterprise applications

package com.example.employee.mapper;

import com.example.employee.dto.EmployeeRequest;
import com.example.employee.dto.EmployeeResponse;
import com.example.employee.entity.Employee;

public class EmployeeMapper {

    private EmployeeMapper() {
    }

    /**
     * Convert Request DTO to Entity
     */
    public static Employee toEntity(EmployeeRequest request) {

        if (request == null) {
            return null;
        }

        Employee employee = new Employee();

        employee.setEmployeeName(request.getEmployeeName());
        employee.setEmail(request.getEmail());
        employee.setSalary(request.getSalary());
        employee.setDepartmentId(request.getDepartmentId());

        return employee;
    }

    /**
     * Convert Entity to Response DTO
     */
    public static EmployeeResponse toResponse(Employee employee) {

        if (employee == null) {
            return null;
        }

        return EmployeeResponse.builder()
                .employeeId(employee.getEmployeeId())
                .employeeName(employee.getEmployeeName())
                .email(employee.getEmail())
                .salary(employee.getSalary())
                .departmentId(employee.getDepartmentId())
                .build();
    }
}

Step 1: Add OpenFeign Dependency

In employee-service, add:

Step 2: Enable Feign

Step 4: DepartmentFeignClient.java
package com.example.employee.feign;

import com.example.employee.dto.DepartmentResponse;
import org.springframework.cloud.openfeign.FeignClient;
import org.springframework.web.bind.annotation.*;

@FeignClient(name = "DEPARTMENT-SERVICE")
public interface DepartmentFeignClient {

    @GetMapping("/api/departments/{id}")
    DepartmentResponse getDepartmentById(
            @PathVariable("id") Long id);

}
Why name = "DEPARTMENT-SERVICE"?

Because in department-service:

spring.application.name=DEPARTMENT-SERVICE

Eureka registers the service with this name.

Employee Service asks Eureka:

"Where is DEPARTMENT-SERVICE?"

Eureka responds with something like:

localhost:8082

Feign then automatically calls it.

Step 5: Inject Feign Client

Inside EmployeeServiceImpl

@Service
@RequiredArgsConstructor
public class EmployeeServiceImpl
        implements EmployeeService {

    private final EmployeeRepository repository;

    private final DepartmentFeignClient departmentFeignClient;

}

Spring injects the implementation automatically.

Step 6: Call Department Service
DepartmentResponse department =
        departmentFeignClient.getDepartmentById(
                employee.getDepartmentId());

No URL.

No RestTemplate.

No WebClient.

Just one method call.

Step 7: Build Combined Response
Employee employee =
        repository.findById(id)
                .orElseThrow(...);

DepartmentResponse department =
        departmentFeignClient.getDepartmentById(
                employee.getDepartmentId());

EmployeeDepartmentResponse response =
        EmployeeDepartmentResponse.builder()
                .employee(
                        EmployeeMapper.toResponse(employee))
                .department(department)
                .build();

return response;

Why OpenFeign Instead of RestTemplate?
RestTemplate	OpenFeign
Manual HTTP calls	Declarative interface
More boilerplate	Less code
Manual URL management	Uses Eureka service names
Harder to maintain	Cleaner and easier to test
Deprecated for new development	Recommended for Spring Cloud microservices
