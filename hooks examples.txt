


React useReducer() Hook – Basic Examples
What is useReducer()?
The useReducer() hook is used to manage complex state logic in React components.

It is an alternative to useState() when:

Multiple state values are related.

State updates are complex.

Different actions modify the same state.

Why do we need useReducer()?
Suppose you have a counter with multiple operations:

Increment

Decrement

Reset

Using useState():

const [count, setCount] = useState(0);
You need multiple update functions.

Using useReducer(), all updates are handled in one place using a reducer function.

Syntax
import { useReducer } from "react";

const [state, dispatch] = useReducer(reducer, initialState);
Parameters
reducer → Function that updates the state.

initialState → Initial value of the state.

state → Current state.

dispatch() → Sends an action to the reducer.

Structure of a Reducer
function reducer(state, action) {

    switch(action.type){

        case "increment":
            return state + 1;

        case "decrement":
            return state - 1;

        case "reset":
            return 0;

        default:
            return state;
    }
}
Example 1: Simple Counter
import { useReducer } from "react";

function reducer(state, action) {

    switch(action.type){

        case "increment":
            return state + 1;

        case "decrement":
            return state - 1;

        case "reset":
            return 0;

        default:
            return state;
    }
}

function App(){

    const [count, dispatch] = useReducer(reducer, 0);

    return(

        <div>

            <h2>Count : {count}</h2>

            <button onClick={() => dispatch({type:"increment"})}>
                Increment
            </button>

            <button onClick={() => dispatch({type:"decrement"})}>
                Decrement
            </button>

            <button onClick={() => dispatch({type:"reset"})}>
                Reset
            </button>

        </div>

    );
}

export default App;

Example 3: Manage Object State
import { useReducer } from "react";

const initialState = {
    name:"",
    age:0
};

function reducer(state, action){

    switch(action.type){

        case "setName":
            return {
                ...state,

            };

        case "setAge":
            return {
                ...state,
                age:action.payload
            };

        default:
            return state;
    }
}

function App(){

    const [user, dispatch] = useReducer(reducer, initialState);

    return(

        <div>

                onClick={() =>
                dispatch({
                    type:"setName",
                    payload:"Scott"

            <button
                onClick={() =>
                dispatch({
                    type:"setAge",
                    payload:30
                })}

                Set Age
            </button>

        </div>

    );
}

export default App;

import { useReducer } from "react";

const initialState = {

};

            </button>

    );
}

useState() vs useReducer()
useState()	useReducer()
Best for simple state	Best for complex state
Easy to learn	Slightly more code
Updates directly	Updates through reducer
Good for one or two values	Good for multiple related values
Uses setState()	Uses dispatch()
Real-Time Use Cases
Use useReducer() for:

🛒 Shopping cart

👤 User profile management

📋 Employee forms

📝 Multi-step forms

🔐 Authentication state

🎮 Game state management

📊 Dashboard filters

Advantages
Centralizes state update logic in one reducer function.

Makes complex state easier to manage.

Predictable and easier to debug.

Scales well as applications grow.

Limitations
More boilerplate than useState() for simple state.

Reducer functions should remain pure (avoid side effects).

Hook Comparison
Hook	Purpose
useState()	Manage simple component state
useEffect()	Perform side effects
useRef()	Store mutable values and access DOM elements
useContext()	Share data across components
useReducer()	Manage complex state with actions and reducers
Key Points to Remember
useReducer() accepts a reducer function and an initial state.

The reducer receives (state, action) and returns the new state.

Use dispatch() to send actions to the reducer.

Actions typically have a type and can include additional data such as payload.

Prefer useReducer() over useState() when state logic becomes complex or involves multiple related updates.


useCallback() hook

React useCallback() Hook – Basic Examples
What is useCallback()?
The useCallback() hook is used to memoize (remember) a function so that React does not recreate the function on every component re-render.

It improves performance by preventing unnecessary function creation and unnecessary re-renders of child components.

Why do we need useCallback()?
Normally, whenever a component re-renders, all functions inside it are recreated.

Without useCallback()
Render 1
↓

create increment()

↓

Render 2
↓

create increment() again

↓

Render 3
↓

create increment() again
Even though the function logic is the same, React creates a new function object every render.

With useCallback()
Render 1
↓

Create increment()

↓

Render 2
↓

Reuse same increment()

↓

Render 3
↓

Reuse same increment()
The function is recreated only when its dependencies change.

Syntax
import { useCallback } from "react";

const memoizedFunction = useCallback(() => {

    // function body

}, [dependencies]);
Parameters
Function → The function to memoize.

Dependency Array → When dependencies change, React creates a new function.

Example 1: Basic Example
import { useState, useCallback } from "react";

function App() {

    const [count, setCount] = useState(0);

    const sayHello = useCallback(() => {
        console.log("Hello React");
    }, []);

    return (

        <div>

            <h2>Count : {count}</h2>

            <button
                onClick={() => setCount(count + 1)}>
                Increment
            </button>

            <button onClick={sayHello}>
                Say Hello
            </button>

        </div>

    );
}

export default App;
Output
Count : 0

Increment

Count : 1

Click Say Hello

Hello React
The sayHello function is created only once because the dependency array is empty ([]).

Real-Time Use Cases
Use useCallback() for:

Passing callback functions to child components.

Optimizing components wrapped with React.memo().

Event handlers for large lists.

Expensive UI rendering.

Dashboard and enterprise applications with many nested components.

useCallback() vs Normal Function
Normal Function	useCallback()
New function created on every render	Function is reused until dependencies change
May trigger child re-renders	Helps avoid unnecessary child re-renders
Simpler code	Adds optimization when needed
useMemo() vs useCallback()
useMemo()	useCallback()
Memoizes a computed value	Memoizes a function
Returns a value	Returns a function
Used for expensive calculations	Used for callback optimization
Advantages
Improves performance by reusing function references.

Helps React.memo() work effectively.

Reduces unnecessary re-renders in child components.

Useful in large applications with complex component trees.

Limitations
Adds complexity if used everywhere.

Provides little or no benefit for simple components.

Incorrect dependency arrays can lead to stale values or bugs.

Hook Comparison
Hook	Purpose
useState()	Store component state
useEffect()	Handle side effects
useRef()	Store mutable values and access DOM elements
useContext()	Share data across components
useReducer()	Manage complex state
useCallback()	Memoize functions
Key Points to Remember
useCallback() returns a memoized function.

The function is recreated only when dependencies change.

It is most useful when passing callbacks to memoized child components (React.memo()).

Do not use useCallback() everywhere—use it only when it provides a measurable performance benefit.

Remember the difference:

useMemo() → Memoizes values

useCallback() → Memoizes functions


useMemo() hook

React useMemo() Hook – Basic Examples
What is useMemo()?
The useMemo() hook is used to memoize (cache) the result of an expensive calculation so that React does not recalculate it on every component re-render.

It improves performance by recomputing the value only when its dependencies change.

Why do we need useMemo()?
Normally, every time a component re-renders, all calculations inside it run again.

Without useMemo()
Render 1
↓

Calculate Total

↓

Render 2
↓

Calculate Total Again

↓

Render 3
↓

Calculate Total Again
Even if the calculation result doesn't change, React recalculates it.

With useMemo()
Render 1
↓

Calculate Total

↓

Render 2
↓

Reuse Cached Value

↓

Render 3
↓

Reuse Cached Value
The calculation runs again only if the dependencies change.

Syntax
import { useMemo } from "react";

const memoizedValue = useMemo(() => {

    // Expensive calculation

    return result;

}, [dependencies]);
Parameters
Function → Returns the calculated value.

Dependency Array → If dependencies change, React recalculates the value.

Example 1: Basic Example
import { useState, useMemo } from "react";

function App() {

    const [count, setCount] = useState(0);

    const square = useMemo(() => {

        console.log("Calculating...");

        return count * count;

    }, [count]);

    return (

        <div>

            <h2>Count : {count}</h2>

            <h2>Square : {square}</h2>

            <button
                onClick={() => setCount(count + 1)}>
                Increment
            </button>

        </div>

    );
}

export default App;

Example 4: Filtering a List
import { useState, useMemo } from "react";

function App() {

    const [search, setSearch] = useState("");

    const employees = [
        "Scott",
        "John",
        "Smith",
        "Martin",
        "Allen"
    ];

    const filteredEmployees = useMemo(() => {

        console.log("Filtering...");

        return employees.filter(emp =>
            emp.toLowerCase().includes(search.toLowerCase())
        );

    }, [search]);

    return (

        <div>

            <input
                type="text"
                placeholder="Search"
                onChange={(e) => setSearch(e.target.value)}
            />

            <ul>

                {filteredEmployees.map(emp => (

                    <li key={emp}>
                        {emp}
                    </li>

                ))}

            </ul>

        </div>

    );
}

export default App;
Output
Search : Sc

Filtering...

Scott
The filtering runs only when the search text changes.
