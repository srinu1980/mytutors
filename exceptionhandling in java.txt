2. What is Inheritance?

Inheritance is the mechanism by which one class acquires the properties and methods of another class.

Java uses the extends keyword.

Basic syntax

    // methods
}

class Child extends Parent {
    // additional properties
    // additional methods
}

9. Does Java support Multiple Inheritance?

Java does not support multiple inheritance through classes.

This is not allowed:

class A {
}

class B {
}

class C extends A, B {   // ERROR
}

Why?

Because of the Diamond Problem / ambiguity.

       A       B
        \     /
          C

Suppose both A and B contain:

void display()

Then:

C c = new C();

c.display();

Which display() should execute?

Java avoids this ambiguity by not allowing multiple inheritance with classes.

However, Java supports multiple inheritance through interfaces.

interface A {
    void display();
}

interface B {
    void display();
}

class C implements A, B {

    public void display() {
        System.out.println("C display");
    }
}

11. Compile-Time Polymorphism

Compile-time polymorphism is achieved through method overloading.

Example:

class Calculator {

    int add(int a, int b) {
        return a + b;
    }

    int add(int a, int b, int c) {
        return a + b + c;
    }

    double add(double a, double b) {
        return a + b;
    }
}

Now:

Calculator c = new Calculator();

System.out.println(c.add(10, 20));

System.out.println(c.add(10, 20, 30));

System.out.println(c.add(10.5, 20.5));

Output:

30
60
31.0

Same method name:

add()

Different parameter lists.

That's method overloading.

12. What can change in Method Overloading?

You can change:

Number of parameters

}
Data type
void display(int a) {
}

void display(double a) {
}
Order of parameters
void display(int a, double b) {
}

void display(double a, int b) {
}

But this is not overloading:

int display(int a) {
    return a;
}

double display(int a) {
    return a;
}

Only return type is different.

❌ Not allowed.

Cat meows
14. The Most Important Concept: Parent Reference → Child Object

Look carefully at this:

Animal a = new Dog();

This is the foundation of runtime polymorphism.

The reference type is:

Animal

The actual object is:

Dog

Diagram:

Animal a
   |
   | reference
   ↓
+-----------+
|   Dog     |
|           |
| sound()   |
+-----------+

Now:

a.sound();

Which sound() executes?

Dog's sound() executes.

Output:

Dog barks

Why?

Because Java determines the overridden instance method based on the actual object at runtime.

21. How to access the child-specific method?

We can use casting:

Animal a = new Dog();

This is called downcasting.

But you should be careful.

Animal a = new Cat();

ClassCastException

because the actual object is Cat, not Dog.

22. Upcasting

This is very common and safe:

Dog d = new Dog();

Animal a = d;

or simply:

Animal a = new Dog();

This is called upcasting.

        Animal

Child → Parent reference.

23. @Override Annotation

When overriding a method, we normally use:

@Override
void sound() {
    System.out.println("Dog barks");
}

Why?

It tells the compiler:

"I intend to override a parent method."

If you accidentally make a mistake:

@Override
void sounds() {
}

The compiler will identify the problem.

So @Override improves safety and readability.

24. Method Overloading vs Overriding

This is a must-know interview comparison.

Feature	Overloading	Overriding
Polymorphism	Compile-time	Runtime
Class relationship	Usually same class	Parent-child
Method name	Same	Same
Parameters	Must be different	Normally same
Return type	Cannot differ only by return type	Same/covariant
Inheritance required?	No	Yes
Binding	Static/Early binding	Dynamic/Late binding

Simple memory trick:

OVERLOADING  → Same class → Different parameters
OVERRIDING   → Parent/Child → Same method signature

26. super Keyword

Explain step by step java Exception handling with examples

Absolutely. Let's learn Java Exception Handling from the very basics to interview level, step by step.

1. What is an Exception?

An exception is an unexpected event that occurs during program execution and disrupts the normal flow of the program.

Example:

public class Test {

    public static void main(String[] args) {

        int a = 10;
        int b = 0;

        int result = a / b;

        System.out.println(result);
    }
}

Here:

int result = a / b;

causes:

ArithmeticException: / by zero

The program terminates abnormally.

2. Why do we need Exception Handling?

Consider:

int a = 10;
int b = 0;

System.out.println(a / b);

System.out.println("Hello");

Because of the exception, "Hello" is never executed.

Exception handling allows us to handle the problem gracefully:

Normal Program
      |
      ↓
Exception occurs
      |
      ↓
Handle Exception
      |
      ↓
Continue / terminate gracefully
3. Exception Handling Keywords

Java provides five important keywords:

try
catch
finally
throw
throws

Remember:

try     → risky code
catch   → handle exception
finally → cleanup
throw   → explicitly create/throw exception
throws  → declare possible exception
4. try and catch

The basic syntax is:

try {
    // risky code
}
catch (Exception e) {
    // exception handling
}

Example:

public class Test {

    public static void main(String[] args) {

        try {

            int result = 10 / 0;

            System.out.println(result);

        } catch (ArithmeticException e) {

            System.out.println("Cannot divide by zero");
        }

        System.out.println("Program continues...");
    }
}

Output:

Cannot divide by zero
Program continues...

Instead of the program terminating, the exception is handled.

5. What happens internally?

Consider:

try {
    int result = 10 / 0;
}
catch (ArithmeticException e) {
    System.out.println("Exception handled");
}

Execution:

          try block
             |
             ↓
        10 / 0
             |
             ↓
    ArithmeticException
             |
             ↓
       catch block
             |
             ↓
    Exception handled

Once an exception occurs inside try, Java immediately stops executing the remaining statements in that try block and searches for a matching catch.

This is wrong:

Because Exception can already catch ArithmeticException.

Correct:

19. Example of Checked Exception

Suppose we read a file:

import java.io.FileReader;

public class Test {

    public static void main(String[] args) {

        FileReader reader = new FileReader("data.txt");
    }
}

This causes a compilation error because FileReader can throw a checked exception.

We can handle it:

import java.io.FileReader;
import java.io.IOException;

public class Test {

    public static void main(String[] args) {

        try {

            FileReader reader =
                    new FileReader("data.txt");

        } catch (IOException e) {

            System.out.println("File problem");
        }
    }
}
20. Unchecked Exceptions

Unchecked exceptions occur at runtime.

They are subclasses of:

RuntimeException

Examples:

ArithmeticException
NullPointerException
ArrayIndexOutOfBoundsException
NumberFormatException
ClassCastException

Example:

int x = 10 / 0;

No compiler error.

But at runtime:

32. Important Interview Question – Can finally be skipped?

Normally finally executes.

But there are exceptional situations, such as JVM termination:

try {

    System.out.println("Try");

    System.exit(0);

}
finally {

    System.out.println("Finally");
}

Here finally will not execute because:

System.exit(0);

terminates the JVM.

33. Exception Propagation

Suppose:

method1()
   ↓
method2()
   ↓
method3()

And exception occurs in method3().

method1()
   |
   ↓
method2()
   |
   ↓
method3()
   |
   ↓
Exception

Java searches for a handler.

If method3() doesn't handle it:

method3()
   ↓
method2()
   ↓
method1()
   ↓
main()

This is called exception propagation.

Example:

static void method3() {

    int x = 10 / 0;
}

static void method2() {

    method3();
}

static void method1() {

    method2();
}

public static void main(String[] args) {

    try {

        method1();

    } catch (ArithmeticException e) {

        System.out.println(
                "Exception handled in main"
        );
    }
}

Output:

Exception handled in main

The exception propagated from method3() to main().

1. First: Why do we need throw and throws?

Suppose we have a method:

void withdraw(double amount) {
    // business logic
}

If the amount is greater than the balance, we want to indicate a problem.

We can explicitly throw an exception:

throw new RuntimeException("Insufficient balance");

That's throw.

But suppose a method can generate a checked exception, such as IOException. We need to tell the caller:

"This method may produce an IOException. You must handle it."

We use:

throws IOException

That's throws.

So the basic difference is:

throw  → Actually throws an exception
throws → Declares that a method may throw an exception
2. What is throw?

throw is a Java keyword used to explicitly throw an exception object.

Syntax
throw new ExceptionType("message");

Example:

public class Test {

    public static void main(String[] args) {

        int age = 15;

        if (age < 18) {

            throw new RuntimeException(
                    "Age must be 18 or above"
            );
        }

        System.out.println("Eligible");
    }
}

Output:

Exception in thread "main"
java.lang.RuntimeException: Age must be 18 or above

Here:

throw new RuntimeException(...)

means:

Create a RuntimeException object.
Throw that object.
Stop the current normal execution flow.
Search for an appropriate exception handler.
3. throw with try-catch

Usually, we handle the thrown exception.

public class Test {

    public static void main(String[] args) {

        try {

            int age = 15;

            if (age < 18) {
                throw new RuntimeException(
                        "Age must be 18 or above"
                );
            }

            System.out.println("Eligible");

        } catch (RuntimeException e) {

            System.out.println(e.getMessage());
        }

        System.out.println("Program continues...");
    }
}

Output:

Age must be 18 or above
Program continues...

Flow:

main()
  |
  ↓
age < 18
  |
  ↓
throw
  |
  ↓
RuntimeException
  |
  ↓
catch
  |
  ↓
Program continues
4. throw is useful for business validation

This is where throw becomes very useful in real applications.

Suppose we have a bank account:

class BankAccount {

    private double balance = 5000;

    void withdraw(double amount) {

        if (amount <= 0) {

            throw new IllegalArgumentException(
                    "Amount must be greater than zero"
            );
        }

        if (amount > balance) {

            throw new IllegalArgumentException(
                    "Insufficient balance"
            );
        }

        balance -= amount;

        System.out.println(
                "Remaining balance: " + balance
        );
    }
}

Usage:

public class Test {

    public static void main(String[] args) {

        BankAccount account = new BankAccount();

        try {

            account.withdraw(6000);

        } catch (IllegalArgumentException e) {

        }
    }

Insufficient balance

The application itself decides when to throw the exception.

5. What is throws?

throws is used in a method declaration to indicate that the method may throw one or more exceptions.

Syntax:

returnType methodName() throws ExceptionType {
}

Example:

void readFile() throws IOException {
    // file reading
}

It means:

"This method may throw IOException. Whoever calls this method must handle it or declare it further."

6. Simple throws Example

Consider reading a file:

import java.io.FileReader;
import java.io.IOException;

class FileService {

    void readFile() throws IOException {

        FileReader reader =
                new FileReader("data.txt");

        System.out.println("File opened");
    }
}

Now the caller must deal with IOException.

public class Test {

    public static void main(String[] args) {

        FileService service = new FileService();

        try {

            service.readFile();

        } catch (IOException e) {

            System.out.println(
                    "Unable to read file"
            );
        }
    }
}

Here:

void readFile() throws IOException

doesn't itself handle the exception.

It declares the possibility of the exception.

7. throws does NOT throw the exception by itself

This is very important.

When you write:

void readFile() throws IOException {
}

you are saying:

"This method may throw IOException."

You are not saying:

"Throw IOException right now."

Actual throwing is done using:

throw new IOException();
8. throw + throws together

This is one of the best examples to understand both.

import java.io.IOException;

class FileService {

    void readFile() throws IOException {

        boolean fileAvailable = false;

        if (!fileAvailable) {

            throw new IOException(
                    "File not available"
            );
        }

        System.out.println("Reading file...");
    }
}

Notice:

throws IOException

and:

throw new IOException(...)

are doing different jobs.

throws
void readFile() throws IOException

Declares the exception.

throw
throw new IOException("File not available");

Actually throws the exception.

12. throw with Checked Exception

Suppose:

import java.io.IOException;

public class Test {

    public static void main(String[] args) {

        throw new IOException("File error");
    }
}

This won't compile.

Why?

Because IOException is a checked exception.

You need to handle it:

import java.io.IOException;

public class Test {

    public static void main(String[] args) {

        try {

            throw new IOException("File error");

        } catch (IOException e) {

            System.out.println(e.getMessage());
        }
    }
}

Or declare it:

import java.io.IOException;

public class Test {

    public static void main(String[] args)
            throws IOException {

        throw new IOException("File error");
    }
}

This demonstrates how throw and throws can work together.
