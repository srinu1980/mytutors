Spring Boot Dependency Injection

Dependency Injection is a design pattern used by Spring to provide
required dependencies to an object.

Spring provides dependencies through the Spring IoC container.

There are three common types of dependency injection:

1. Constructor Injection
2. Setter Injection
3. Field Injection

Constructor injection is generally preferred because dependencies
can be made immutable and required dependencies are explicit.

Example:

@Service
public class EmployeeService {

    private final EmployeeRepository repository;

    public EmployeeService(EmployeeRepository repository) {
        this.repository = repository;
    }
}

llm_client = OpenAI()

chroma_client = chromadb.PersistentClient(
    path="./chroma_db"
)

collection = chroma_client.get_or_create_collection(
    name="spring_boot"
)


# --------------------------------
# 2. Read document
# --------------------------------

with open(
    "documents/spring_boot_notes.txt",
    "r",
    encoding="utf-8"
) as file:
    text = file.read()


# --------------------------------
# 3. Split document
# --------------------------------

chunks = [
    text[i:i + 500]
    for i in range(0, len(text), 500)
]


# --------------------------------
# 4. Store documents
# --------------------------------

collection.add(
    documents=chunks,
    ids=[
        f"chunk-{i}"
        for i in range(len(chunks))
    ]
)


# --------------------------------
# 5. Ask question
# --------------------------------

question = "What is constructor injection?"


# --------------------------------
# 6. Retrieve relevant chunks
# --------------------------------

results = collection.query(
    query_texts=[question],
    n_results=3
)


# --------------------------------
# 7. Build context
# --------------------------------

context = "\n\n".join(
    results["documents"][0]
)


# --------------------------------
# 8. Build prompt
# --------------------------------

prompt = f"""
You are a Java trainer.

Answer the question using only the
provided context.

Context:
{context}

Question:
{question}

If the answer is not present in the
context, say so.
"""


# --------------------------------
# 9. Ask LLM
# --------------------------------

response = llm_client.chat.completions.create(
    model="your-model",
    messages=[
        {
            "role": "user",
            "content": prompt
        }
    ]
)


# --------------------------------
# 10. Print answer
# --------------------------------

print(
    response.choices[0].message.content
)

This is a learning example, not yet a production-grade RAG implementation.

21. Very Important: Separate Ingestion and Query

In a real application, don't re-process your documents every time a user asks a question.

There are actually two pipelines.

Pipeline A — Ingestion

Run when documents are uploaded/updated:

  │
  ▼
Document Loader
  │
  ▼
Chunking
  │
  ▼

  │
  ▼

Run every time the user asks something:

      │
      ▼

      │
      ▼
Vector Search
      │
      ▼
Relevant Chunks
      │
      ▼
Prompt
      │
      ▼
LLM
      │
      ▼
Answer

This distinction is very important in interviews.

23. Where Does RAG Actually Start?

This is a common interview confusion.

The document ingestion pipeline prepares the knowledge.

The RAG query pipeline retrieves that knowledge and augments the LLM prompt.

So:

INGESTION

Documents
   ↓
Chunks
   ↓
Embeddings
   ↓
Vector Store

then:

RAG

Question
   ↓
Retrieve
   ↓
Augment
   ↓
Generate
24. Add Query Expansion

Now suppose the student asks:

"JWT?"

That's too short.

We can expand it:

JWT
 │
 ├── JSON Web Token
 ├── JWT Authentication
 ├── Bearer Token
 ├── Access Token
 ├── Refresh Token
 └── Spring Security JWT

Then retrieve using these related queries.

             JWT
              │
              ▼
        Query Expansion
              │
     ┌────────┼─────────┐
     ▼        ▼         ▼
    JWT     Bearer    Spring
            Token     Security
     │        │         │
     └────────┼─────────┘
              ▼
         Vector Search

This can improve recall, although it also adds latency and can introduce irrelevant results if the expansion is poor.

25. Add Re-ranking

Suppose retrieval returns:

1. Spring Security
2. OAuth
3. JWT
4. React Authentication
5. Docker Security

A re-ranker can reorder them:

1. JWT
2. Spring Security
3. OAuth
4. Docker Security
5. React Authentication

Then only the best few chunks are passed to the LLM.

Vector Search
     │
     ▼
20 candidates
     │
     ▼
Re-ranker
     │
     ▼
Top 5
     │
     ▼
LLM

27. RAG vs Fine-Tuning

Suppose your company changes its HR policy every month.

You could fine-tune a model, but that would be inconvenient for frequently changing knowledge.

RAG is usually a better fit:

New Policy
    │
    ▼
Chunk
    │
    ▼
Embedding
    │
    ▼
Vector DB

No model retraining is required just to make the new document retrievable.

28. Your Evaluation Answer

If the evaluator asks:

"Explain a real-time RAG implementation in Python."

You can answer:

"I would build a document-based question-answering system. First, I load the company's PDF or text documents. I split the documents into smaller chunks and generate embeddings for those chunks. I store the chunks and embeddings in a vector database such as Chroma or pgvector. When a user asks a question, I generate an embedding for the question and perform similarity search against the vector database. I retrieve the most relevant chunks and combine them with the user's question to construct a prompt. The LLM then generates the final answer based on the retrieved context. This is the Retrieval-Augmented Generation pipeline."
