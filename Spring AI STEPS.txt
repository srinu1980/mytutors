The first thing to understand is that Spring AI is not an AI model. Spring AI is a framework that helps Spring Boot applications communicate with AI models and related AI services.

Spring AI — Complete Step-by-Step Learning Path for Beginners

Spring AI is a good next topic after learning Spring Boot, LLMs, Embeddings, and RAG.

The official Spring AI API provides abstractions for chat models, embeddings, vector stores, tool calling, advisors, RAG, ETL, and MCP, with Spring Boot auto-configuration and support for multiple AI providers.

1. First understand: What is Spring AI?
Simple definition

Spring AI is a framework that helps Java and Spring Boot developers integrate AI models into their applications.

For example:

Spring Boot Application
        ↓
      Spring AI
        ↓
   Chat Model / LLM
        ↓
 OpenAI / Ollama / Azure / etc.

Instead of manually calling an AI provider's REST API, Spring AI gives us Spring-friendly abstractions.

2. Why do we need Spring AI?

Imagine without Spring AI:

Java Application
      ↓
Create HTTP Request manually
      ↓
Call AI REST API
      ↓
Create JSON manually
      ↓
Parse JSON Response
      ↓
Handle provider-specific code

With Spring AI:

Java Application
      ↓
   ChatClient
      ↓
    AI Model
      ↓
   Get Response

Example:

String response = chatClient.prompt()
        .user("Explain Java Streams")
        .call()
        .content();

The ChatClient provides a fluent API for communicating with AI models and supports synchronous and streaming interactions.

CONCEPT 1: AI Model / ChatModel
What is an LLM?

LLM means:

Large Language Model

Examples include models from OpenAI, Anthropic, Google, and others.

Your application communicates with an AI model through Spring AI abstractions.

Conceptually:

ChatModel
    ↓
Provider-specific implementation
    ↓
Actual AI Model

Spring AI's Model API is designed to provide portable abstractions across providers, including chat and embedding models.

CONCEPT 2: ChatClient

ChatClient is one of the most important classes in Spring AI.

It is similar in spirit to using a fluent client API.

Basic flow
User Question
      ↓
ChatClient
      ↓
AI Model
      ↓
AI Response
Example
@RestController
public class ChatController {


    private final ChatClient chatClient;


    public ChatController(ChatClient.Builder builder) {
        this.chatClient = builder.build();
    }


    @GetMapping("/ask")
    public String ask(@RequestParam String question) {


        return chatClient.prompt()
                .user(question)
                .call()
                .content();
    }
}

Now call:

GET /ask?question=What is Java?

Flow:

Browser
   ↓
Spring Boot Controller
   ↓
ChatClient
   ↓
AI Model
   ↓
Response

content() returns the response as a String; Spring AI also supports obtaining richer response metadata or mapping responses to Java types.

CONCEPT 3: Prompt

A Prompt is the input we send to an AI model.

Example:

Explain Spring Boot in simple language.

In Spring AI:

String response = chatClient.prompt()
        .user("Explain Spring Boot")
        .call()
        .content();

Flow:

Prompt
   ↓
AI Model processes prompt
   ↓
Generates response
CONCEPT 4: System Message

A system message tells the AI how it should behave.

Example:

You are a Java trainer.
Explain concepts using simple examples.

Code:

String response = chatClient.prompt()
        .system("""
                You are an experienced Java trainer.
                Explain concepts step by step.
                Give simple examples.
                """)
        .user("Explain inheritance")
        .call()
        .content();
Flow
System Message
       +
User Question
       ↓
     Prompt
       ↓
   AI Model
       ↓
   AI Response

The ChatClient API supports system and user messages, prompt templates, options, advisors, and other prompt customization mechanisms.

CONCEPT 5: Prompt Templates

Suppose you want dynamic input.

Instead of:

.user("Explain Java")

You want:

Explain {topic}

Example:

String response = chatClient.prompt()
        .user(u -> u
                .text("Explain {topic} with examples")
                .param("topic", "Java Streams"))
        .call()
        .content();

Now:

{topic}
   ↓
Java Streams

Final prompt:

Explain Java Streams with examples

This is useful when building dynamic AI applications.

CONCEPT 6: Chat Options

Chat models can have options such as:

Model name
Temperature
Other provider-specific settings
What is temperature?

Simple understanding:

Low Temperature
       ↓
More predictable response


High Temperature
       ↓
More creative response

Example:

String response = chatClient.prompt()
        .user("Write a Java learning example")
        .options(options -> options
                .temperature(0.2))
        .call()
        .content();

Use cases:

0.0 - 0.3 → factual / consistent answers


0.4 - 0.7 → balanced


0.8+ → creative generation

Prompt options can include settings such as model selection and temperature.

CONCEPT 7: Structured Output

This is a very important concept.

Normally AI returns text:

Java is an object-oriented programming language...

But sometimes we want a Java object.

For example:

public record Course(
        String name,
        String description,
        int duration
) {
}

Now ask AI:

Create a Java course.

We want:

{
  "name": "Java Full Stack",
  "description": "Java and Spring Boot course",
  "duration": 30
}

Spring AI can map the response to a Java type.

Course course = chatClient.prompt()
        .user("Create a beginner Java course")
        .call()
        .entity(Course.class);
Flow
Prompt
   ↓
AI Model
   ↓
Structured JSON
   ↓
Spring AI
   ↓
Java Object

Spring AI supports entity() methods for mapping responses into Java types, with options for provider-native structured output when supported.

CONCEPT 9: Embeddings

This is where Spring AI becomes more interesting.

What is an embedding?

An embedding converts text into numbers.

Example:

"Java is a programming language"

becomes conceptually:

[0.12, -0.45, 0.89, 0.23, ...]

These numbers represent the semantic meaning of the text.

Example
Java programming
        ↓
Embedding Model
        ↓
[0.21, 0.55, 0.81, ...]

Another sentence:

Java coding language
        ↓
Embedding Model
        ↓
[0.20, 0.56, 0.79, ...]

The vectors may be similar because the meaning is similar.

CONCEPT 10: Vector Store

A vector store stores embeddings.

Traditional database search:

SELECT * FROM documents
WHERE title = 'Java';

Vector search:

Find documents similar to:


"How can I learn Java?"

Architecture:

Documents
    ↓
Embedding Model
    ↓
Vectors
    ↓
Vector Store

When the user asks:

How do I start learning Java?

The question is also converted to an embedding:

Question
   ↓
Embedding
   ↓
Similarity Search
   ↓
Relevant Documents

A vector database performs similarity searches rather than only exact-match queries, and this retrieval pattern is commonly used for RAG.

CONCEPT 11: RAG

RAG means:

Retrieval-Augmented Generation

This is one of the most important concepts to learn.

Problem without RAG

Suppose you ask:

What is my company's leave policy?

The LLM may not know your private company information.

Without RAG:

User Question
      ↓
     LLM
      ↓
Maybe incorrect answer
With RAG
Company Documents
       ↓
   Split Documents
       ↓
    Embeddings
       ↓
   Vector Store
       ↓


User Question
       ↓
   Similarity Search
       ↓
Relevant Documents
       ↓
      LLM
       ↓
   Final Answer

The key idea:

Don't retrain the model for every document. Retrieve relevant information and provide it as context.

Simple Spring AI RAG Example

Conceptually:

String response = chatClient.prompt()
        .advisors(
            QuestionAnswerAdvisor.builder(vectorStore)
                    .build()
        )
        .user("What is the leave policy?")
        .call()
        .content();

The flow is:

User Question
      ↓
QuestionAnswerAdvisor
      ↓
Vector Store Search
      ↓
Relevant Documents
      ↓
Add Context to Prompt
      ↓
LLM
      ↓
Final Answer

Spring AI's QuestionAnswerAdvisor implements a naive RAG pattern by retrieving relevant vector-store content and augmenting the prompt.

CONCEPT 12: Advisors

An Advisor can intercept or enhance the interaction between your application and the AI model.

Think of it like a processing layer.

User Request
      ↓
   Advisor 1
      ↓
   Advisor 2
      ↓
   Advisor 3
      ↓
    AI Model

Examples:

Chat Memory Advisor
       ↓
RAG Advisor
       ↓
Logging Advisor
       ↓
AI Model
Example
ChatClient chatClient = ChatClient.builder(chatModel)
        .defaultAdvisors(
                new SimpleLoggerAdvisor()
        )
        .build();

Spring AI Advisors are designed to encapsulate recurring AI patterns such as memory, RAG, tool calling, and logging. The order of advisors affects how data flows through the chain.

CONCEPT 13: Chat Memory

Normally, an LLM does not automatically remember a previous API call.

Example:

Request 1
My name is Srinivasa.
Request 2
What is my name?

Without conversation history, the model may not know.

Solution: Chat Memory
User: My name is Srinivasa
         ↓
      Memory
         ↓


User: What is my name?
         ↓
Previous Conversation
         +
Current Question
         ↓
         LLM

Conceptually:

chatClient.prompt()
        .advisors(a -> a
                .advisors(memoryAdvisor)
                .param(ChatMemory.CONVERSATION_ID, "user-123"))
        .user("What is my name?")
        .call()
        .content();

When using Spring AI memory advisors, the conversation ID is supplied to identify the conversation context.

CONCEPT 14: Tool Calling

This is one of the most powerful concepts.

An LLM can generate text, but it cannot directly access your database or execute your Java methods by itself.

Tool calling connects the AI model to your application functions.

Example question:

What is the weather in Chennai?

Flow:

User
  ↓
LLM
  ↓
"I need weather information"
  ↓
Call Java Method / API
  ↓
Weather Result
  ↓
LLM
  ↓
Final Response
Example Java Tool
@Component
public class WeatherTools {


    @Tool(description = "Get current weather for a city")
    public String getWeather(String city) {


        // In real application,
        // call weather API


        return "The weather in " + city + " is 32°C";
    }
}

Use the tool:

String response = chatClient.prompt()
        .user("What is the weather in Chennai?")
        .tools(weatherTools)
        .call()
        .content();
Tool Calling Flow
User:
"What is weather in Chennai?"
          ↓
         LLM
          ↓
Decides to call:


getWeather("Chennai")
          ↓
Java Method
          ↓
"32°C"
          ↓
         LLM
          ↓
Final Response

Spring AI supports tool calling through abstractions that expose tool definitions to the model and execute selected tools, returning their results to the model for the final answer. With ChatClient, the tool-calling loop can be handled automatically.

Step 7: Create Our First AI Controller

Create:

controller/ChatController.java

Code:

package com.example.ai.controller;


import org.springframework.ai.chat.client.ChatClient;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.RestController;


@RestController
public class ChatController {


    private final ChatClient chatClient;


    public ChatController(ChatClient.Builder chatClientBuilder) {


        this.chatClient = chatClientBuilder.build();


    }


    @GetMapping("/ask")
    public String askAI(
            @RequestParam String question) {


        return chatClient
                .prompt()
                .user(question)
                .call()
                .content();
    }
}

ChatClient.Builder can be auto-configured by Spring AI, and the prompt() → user() → call() → content() flow sends the user input to the configured AI model and returns the generated text.

Step 10: Better API Response

Instead of returning only a String, let's return JSON.

package com.example.ai.controller;


import java.util.Map;


import org.springframework.ai.chat.client.ChatClient;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.RestController;


@RestController
public class ChatController {


    private final ChatClient chatClient;


    public ChatController(ChatClient.Builder builder) {
        this.chatClient = builder.build();
    }


    @GetMapping("/ask")
    public Map<String, String> askAI(
            @RequestParam String question) {


        String answer = chatClient
                .prompt()
                .user(question)
                .call()
                .content();


        return Map.of(
                "question", question,
                "answer", answer
        );
    }
}

  "question": "What is Spring Boot?",
  "answer": "Spring Boot is a framework..."

8. A More Realistic Prompt Template

For an AI learning application, we can create a richer template:

String prompt = """
        You are teaching {topic}.


        Student level: {level}


        Response language: {language}


        Response format: {format}


        Follow this structure:


        1. Definition
        2. Why do we need it?
        3. Important concepts
        4. Simple example
        5. Code explanation
        6. Real-time use case
        7. Common mistakes
        8. Interview question


        Adapt the complexity of the answer
        based on the student's level.
        """;

        .param("format", format))
