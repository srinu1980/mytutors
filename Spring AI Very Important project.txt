A prompt is the input/instruction given to the LLM.

2. What is Prompt Engineering?
Prompt Engineering is the practice of designing instructions and context so that an LLM produces useful, consistent, and controlled results.

For example, a weak prompt:

Explain Spring.
A better prompt:

Explain Spring Framework to a Java beginner.
Include:
1. Definition
2. Main features
3. Dependency Injection
4. Example
5. Interview question
The second prompt provides:

Role

+

+
Output requirements

10. ChatClient configuration
Now let's improve our ChatClient.

Instead of creating it directly inside the service, create a configuration class.

package com.example.aichatbot.config;

import org.springframework.ai.chat.client.ChatClient;
import org.springframework.ai.chat.memory.ChatMemory;
import org.springframework.ai.chat.client.advisor.MessageChatMemoryAdvisor;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration
public class ChatClientConfig {

    @Bean
    public ChatClient chatClient(
            ChatClient.Builder builder,
            ChatMemory chatMemory) {

        return builder
                .defaultAdvisors(
                        MessageChatMemoryAdvisor.builder(chatMemory)
                                .build()
                )
                .defaultSystem("""
                        You are an expert Java and Spring Boot
                        corporate trainer.

                        Explain concepts clearly and systematically.

                        Use practical examples.
                        Prefer Java 21 examples.
                        Provide interview points when appropriate.
                        """)
                .build();
    }
}
Now ChatService can simply inject:

ChatClient
11. Simplified ChatService
@Service
public class ChatService {

    private final ChatClient chatClient;

    public ChatService(ChatClient chatClient) {
        this.chatClient = chatClient;
    }

    public String ask(
            String conversationId,
            String message) {

        return chatClient
                .prompt()
                .user(message)
                .advisors(advisor ->
                        advisor.param(
                                ChatMemory.CONVERSATION_ID,
                                conversationId))
                .call()
                .content();
    }
}
This is much cleaner.

13. Temperature
Now we come to an important LLM parameter:

temperature
Temperature controls how deterministic vs variable the model's output tends to be.

Conceptually:

Temperature = LOW
       ↓
More predictable
More focused
More consistent
while:

Temperature = HIGH
       ↓
More variation
More creative
Less deterministic
For a Java technical assistant, we generally want relatively focused responses.

For example:

Technical explanation
      ↓
Low/moderate temperature
For:

Creative story
      ↓
Higher temperature
The exact useful range depends on the model and task; don't assume that a particular numeric value has the same effect across all models.

30. What you should understand for interviews
Question 1
What is Prompt Engineering?

Answer:

Prompt Engineering is the process of designing effective instructions, context, constraints, and output requirements to guide an LLM toward useful and consistent results.

Question 2
What is a system prompt?

A system prompt provides high-level instructions that define the behavior, role, or constraints of the AI assistant.

Question 3
What is a user prompt?

The user prompt contains the user's actual request or task.

Question 4
System prompt vs user prompt?

System → Behavior / role / rules

User → Current task / question
Question 5
What is temperature?

Temperature is a model-generation parameter that influences the variability or randomness of generated responses. Lower values generally favor more predictable output, while higher values allow more variation.

Question 6
What is a context window?

A context window is the amount of input and conversational context that a model can consider for a request, subject to the model's supported limits.

Question 7
Why are tokens important?

Tokens are the units used by language models to process text. Token counts affect context usage, latency, and often API cost.

Question 8
Why use structured output?

Structured output makes model responses predictable and easier for backend applications and frontends to consume.

Part 5 — Streaming AI Responses with Spring Boot + React
Now we move from a normal chatbot to a ChatGPT-like experience, where the answer appears gradually instead of waiting for the complete response.

In our previous implementation we used:

.call()
.content()
That waits for the complete AI response.

With streaming, we use:

.stream()
.content()
Spring AI currently exposes streaming responses as a reactive Flux<String>. Streaming requires the reactive stack, so our Spring Boot application needs spring-boot-starter-webflux in addition to the existing servlet stack if we want to keep the rest of the application unchanged.

9. React Streaming Function
const sendStreamingMessage = async () => {

    if (!message.trim()) {
        return;
    }

    const userMessage = message;

    setMessage("");

    const response = await fetch(
        "http://localhost:8080/api/chat/stream",
        {
            method: "POST",
            headers: {
                "Content-Type": "application/json"
            },
            body: JSON.stringify({
                conversationId: conversationId,
                message: userMessage
            })
        }
    );

    if (!response.ok) {
        throw new Error("Failed to connect to AI service");
    }

    const reader = response.body.getReader();

    const decoder = new TextDecoder();

    let aiResponse = "";

    while (true) {

        const { value, done } =
            await reader.read();

        if (done) {
            break;
        }

        const chunk =
            decoder.decode(value, { stream: true });

        aiResponse += chunk;

        console.log(chunk);
    }
};
Let's understand this carefully.

10. response.body
When the server sends a streaming response:

response.body
represents the incoming stream.

We then call:

response.body.getReader()
which gives us a reader.

11. reader.read()
We continuously read the stream:

const { value, done } =
    await reader.read();
There are two important properties.

value
Contains the current chunk.

done
Indicates whether streaming has finished.

Example:

value = "Spring"
done = false
Next:

value = " Boot"
done = false
Next:

value = " is"
done = false
Eventually:

done = true
12. Why TextDecoder?
Network data comes as bytes.

We need to convert those bytes into text.

Therefore:

const decoder = new TextDecoder();
Then:

decoder.decode(value, { stream: true });
converts each incoming chunk into text.

14. Complete React Example
A simple component can look like this:

import { useState } from "react";

function Chat() {

    const [message, setMessage] = useState("");
    const [aiResponse, setAiResponse] = useState("");
    const [loading, setLoading] = useState(false);

    const [conversationId] =
        useState(() => crypto.randomUUID());

    const sendMessage = async () => {

        if (!message.trim()) {
            return;
        }

        const userMessage = message;

        setMessage("");
        setAiResponse("");
        setLoading(true);

        try {

            const response = await fetch(
                "http://localhost:8080/api/chat/stream",
                {
                    method: "POST",

                    headers: {
                        "Content-Type":
                            "application/json"
                    },

                    body: JSON.stringify({
                        conversationId,
                        message: userMessage
                    })
                }
            );

            if (!response.ok) {
                throw new Error(
                    "AI request failed"
                );
            }

            const reader =
                response.body.getReader();

            const decoder =
                new TextDecoder();

            let result = "";

            while (true) {

                const {
                    value,
                    done
                } = await reader.read();

                if (done) {
                    break;
                }

                const chunk =
                    decoder.decode(
                        value,
                        { stream: true }
                    );

                result += chunk;

                setAiResponse(result);
            }

        } catch (error) {

            console.error(error);

            setAiResponse(
                "Sorry, something went wrong."
            );

        } finally {

            setLoading(false);
        }
    };

    return (
        <div>

            <h2>Java AI Assistant</h2>

            <textarea
                value={message}
                onChange={(e) =>
                    setMessage(e.target.value)
                }
                placeholder="Ask a Java question..."
            />

            <br />

            <button
                onClick={sendMessage}
                disabled={loading}
            >
                {loading
                    ? "Generating..."
                    : "Send"}
            </button>

            <hr />

            <h3>AI Response</h3>

            <div>
                {aiResponse}
            </div>

        </div>
    );
}

export default Chat;

16. Step 3 — What is an Embedding?
This is probably the most important concept in RAG.

An embedding converts text into a numerical vector representing its semantic meaning.

For example:

"Java dependency injection"
might conceptually become:

[0.12, -0.45, 0.81, 0.17, ...]
Real embeddings contain many dimensions.

The exact numbers aren't important to us.

The important idea is:

Text
 ↓
Embedding Model
 ↓
Vector
17. Why Do We Need Embeddings?
Suppose our document contains:

"Dependency injection allows an object
to receive its dependencies..."
User asks:

How does Spring provide required objects to a class?

Notice:

Question:
How does Spring provide required objects?
and:

Document:
Dependency injection allows an object
to receive its dependencies...
They don't necessarily use the same words.

A simple keyword search may struggle.

But their meaning is similar.

Embeddings allow us to perform semantic similarity search.

18. Semantic Search
Traditional keyword search:

Search:
"required objects"
looks primarily for matching terms.

Semantic search:

Question
 ↓
Embedding
 ↓
Compare vectors
 ↓
Find semantically similar content
So:

"How does Spring provide required objects?"
can retrieve:

"Dependency injection allows an object
to receive its dependencies..."
even though the wording differs.

38. Similarity Search
The vector database calculates how close vectors are.

One common metric is:

Cosine similarity

Conceptually:

Vector A
   ↘
    Similarity
   ↗
Vector B
If two texts have similar meaning, their embeddings should generally be closer in vector space.

You don't need to manually calculate cosine similarity in our application—the vector store handles the search.

But you absolutely should understand the concept for interviews.

40. Common RAG Problems
You should eventually learn how to solve:

1. Poor chunking
Relevant information is split incorrectly.

2. Too much context
Too many irrelevant chunks are retrieved.

3. Too little context
Important information isn't retrieved.

4. Poor metadata
Sources cannot be identified.

5. Duplicate documents
The same content gets indexed multiple times.

6. Incorrect PDF extraction
Tables/images/layouts may not extract correctly.

7. Semantic mismatch
The embedding model may not represent a domain accurately.

8. Hallucination
The LLM may still generate unsupported information.
